What is TinyML?

TinyML is machine learning small enough to run on a tiny chip. A normal AI model can fill gigabytes and needs a data centre. A TinyML model is a few kilobytes of numbers, small enough for a microcontroller like the ESP32-S3 in your scanner, a phone or a web page.

Why it suits a soil scanner: it answers in a fraction of a millisecond, needs no internet connection to think, costs nothing per question, and your readings never have to leave the device for the model to work.

Why it is here on the website now: the scanner's screen can no longer show the on-device results. So the website runs the same three networks on every scan it receives, and you can try them yourself below. Nothing about the maths changed. Only where it runs did.

{# ---------- HOW IT WORKS ---------- #}

How it works, step by step

From a lab dataset to a number on the screen.

Learn once, on a computer

A Python script (tinyml/train_tinyml.py) shows the network 2,200 labelled soil samples from the crop dataset. It nudges its numbers (“weights”) until its guesses match the labels. This takes about two minutes and happens only once.

Save the weights

The trained network is just a list of numbers. They are saved as a C header for the ESP32 and as a small JSON file for the website. Same numbers, two homes.

Rescale the six readings

Each value is turned into “standard steps from average” so no single unit dominates.

Multiply, add, switch

Every neuron multiplies each input by its weight, adds them up plus a bias, and a ReLU switch turns any negative total into 0. That is the hidden layer.

Turn scores into percentages

The output layer gives one score per crop. Softmax converts them into percentages that sum to 100, and the top three are shown.

No learning at scan time

The device or page only uses the numbers. That is why it is so light: a few thousand multiplications, nothing is stored or sent anywhere.

{# ---------- THE THREE NETWORKS ---------- #}

The three networks

All three read the same six values: N, P, K, soil temperature, soil moisture and pH.

Crop recommender

6 → 24 → 22

Ranks the 22 crops and shows the top three with a confidence.

Probe check

6 → 8 → 3 → 8 → 6

An autoencoder: it squeezes the reading through a 3-number bottleneck and tries to rebuild it. It only ever saw real soil, so a reading it cannot rebuild (probe in air, loose contact) is flagged “odd”.

Nutrient advisor

6 → 16 → 8

Names what to fix: low N, P or K, acidic or alkaline, too dry, waterlogged, too hot. It copies the AgriSense threshold rules, so it matches them but does not beat them.

Honest limits

  • Confidence is not correctness. A network always answers. Try “Probe in the air”: it still names a crop, but the probe check flags the reading as odd. Trust the crop only when the probe check is happy.
  • It learned from a reference dataset of 2,200 samples of Philippine crops (built from agronomic ranges), not from measurements on your own farm. Treat the result as a starting point to discuss, not a guarantee.
  • Both models use the same six readings the probe measures: N, P, K, soil temperature, moisture and pH. Rainfall is not used anywhere.
  • The probe check is strong on gross faults (probe in air, random values) but weak on subtle ones: in testing it caught only about a quarter of readings stuck at pH 7 and 100% moisture. Re-scan if something looks wrong.
  • The advisor is the rules in a smaller box. It agrees with them about 99% of the time. Its benefit is working offline, not being smarter.
